# 📰 デジタル・クラス新聞社

児童がタブレットから記事を投稿し、先生がそれを選んで並べ、**A4 の学級新聞として印刷（または PDF 保存）する**ための Google Apps Script（GAS）ウェブアプリです。

Google スプレッドシートをデータベース、Google ドライブを画像置き場として使います。サーバーの用意やインストールは要りません。

操作手順は **[MANUAL.md](MANUAL.md)** に、アクセシビリティの点検記録は **[AUDIT.md](AUDIT.md)** にあります。

---

## このアプリでできること

### 児童（記者ページ / `post.html`）

- タイトル・本文・記者名・タグ・写真（1枚）を送って記事を投稿する
- 漢字にふりがな（ruby）が付いた画面で操作する
- タグは先生が設定したものから 1 つ選ぶ（選択は必須）
- 送信に失敗しても、自動で最大 3 回まで再送を試みる

投稿できるのは**新規の記事だけ**です。児童が自分の記事をあとから直したり消したりする画面はありません。

### 先生（新聞編集室 / `admin.html`）

- 投稿された記事を一覧で見て、**チェックを入れたものだけ**を紙面に載せる
- キーワード（タイトル・記者名）／タグ／投稿日の範囲で絞り込む
- ドラッグ＆ドロップで掲載順を並べ替える
- 紙面の上で、新聞名・発行日・見出し・記者名・本文を**直接書き換える**
- 用紙の向き（A4 縦／横）、縦書き／横書き、段組み（1〜4段）、文字サイズ（8〜24px）を変える
- テーマ 7 種・フォント 5 種・見出しスタイル 6 種から選ぶ
- 記事ごとに写真の位置・大きさ・形を変える／見出しを隠す
- 記事に URL を紐づけて、紙面に **QR コード**を刷り込む（動画などへの導線）
- 「編集後記」のような、投稿によらない**自由記述欄**を足す
- 編集途中の状態に名前を付けて保存し、あとから呼び出す
- レイアウトとデザインだけを**テンプレート**として保存し、別の号に適用する
- 児童画面に出すタグ（絵文字・名前・ふりがな）を編集する
- ブラウザの印刷機能で A4 に印刷、または PDF として保存する

**`index.html` は児童の投稿画面ではありません。** リポジトリ直下の `index.html` は
GitHub Pages が配る導入案内ページで、児童の投稿画面は `post.html` です。
どのファイルを GAS へ送るかは `.claspignore` で決めています
（`npm run gas:status` で確かめられます）。

### 画面の切り替え

`doGet(e)` が `p` パラメータだけを見ます。

| URL | 表示 |
|---|---|
| `https://script.google.com/.../exec` | 記者ページ（`post.html`） |
| `https://script.google.com/.../exec?p=admin` | 新聞編集室（`admin.html`） |

**編集室に入れるのは、メニューで登録したアカウントだけです。** 判定は `Session.getActiveUser().getEmail()` と `TEACHER_EMAILS` の照合で行い、画面の入口だけでなく管理系のサーバー関数ひとつひとつでも同じ検査を通します（`google.script.run` から直接呼ばれても弾くため）。記者ページに編集室へのリンクが出るのも、先生のアカウントで開いたときだけです。詳しくは「[編集室に入れる人](#編集室に入れる人要設定)」を参照してください。

### データの置き場所

同じスプレッドシートの中に、2 つのシートが自動で作られます。

**`Articles` シート**（記事本体。初回投稿時に自動生成）

| 列 | 内容 |
|---|---|
| `ID` | UUID（`Utilities.getUuid()`） |
| `Title` | 記事のタイトル |
| `Body` | 本文 |
| `ImageURL` | 画像の URL（`https://drive.google.com/thumbnail?id=<ファイルID>&sz=w1600`）。写真なしの場合は空 |
| `Reporter` | 記者名 |
| `Timestamp` | 投稿日時 |
| `Status` | 常に `Pending` が書き込まれます（後述） |
| `Tag` | 選ばれたタグ名 |

**列はすべてヘッダー名で読み書きします。列の位置は一切見ません。** 列を入れ替えても、右にメモ用の列を足しても動きます（アプリはそこに何も書きません）。逆に、見つからないヘッダーを「たぶん N 列目」で埋め合わせることもしません。ヘッダーが無ければ「その列は無い」として扱い、点検メニューで気づけるようにしてあります。

シートやヘッダーがそろっているかは、開くたびに自動で確かめます。詳しくは「[シートの点検と修整](#シートの点検と修整)」を参照してください。

**`SystemData` シート**（設定の保存先。非表示シートとして自動生成）

`Type` / `Name` / `Data` / `Date` の 4 列。`Type` は `LAYOUT`（一時保存）か `TEMPLATE`（デザインテンプレート）のどちらかです。

**スクリプトプロパティ**

| キー | 内容 |
|---|---|
| `IMAGE_FOLDER_ID` | 写真の保存先ドライブフォルダの ID |
| `TAG_SETTINGS` | タグ設定の JSON。未設定なら既定の 5 タグ（ニュース／行事／学習／遊び／その他）が使われます |

## 配り方

このアプリは**コンテナバインドスクリプト**です。スクリプトはスプレッドシートに束ねられていて、
**スプレッドシートをコピーすると、コードも設定もいっしょについてきます。**
先生おひとりずつが、ご自分のコピーを、ご自分のアカウントでデプロイして使います。

案内ページ（コピー用のリンク付き）は **<https://digital-newspaper.giga-school.com/>** です。

### A. スプレッドシートをコピーする（推奨）

1. 案内ページの「スプレッドシートをコピーして始める」を押し、**コピーを作成**する
2. できたファイルを開き、**拡張機能 → Apps Script**
3. **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 「次のユーザーとして実行」: **自分**
   - 「アクセスできるユーザー」: **同一ドメインの全員**
4. スプレッドシートを再読み込みすると、**📰 新聞システム** メニューが出ます
5. **2. 先生のメールアドレスを設定** で、ご自分のアカウントを登録する（← 児童に配る前に必ず）
6. **3. 先生用管理画面を開く** … 編集室と投稿画面の URL がダイアログで出ます。児童に配るのは投稿画面のほうだけ

`Articles` / `SystemData` シートも、写真フォルダも自動で用意されます。
場所を決めたいときだけ **1. 写真フォルダの設定** でフォルダ ID を指定してください。

### B. ファイルを貼り付ける

学校のポリシーで外部ファイルのコピーが禁じられている場合は、こちらでも入ります。

1. Google スプレッドシートを新規作成する
2. **拡張機能 → Apps Script** を開く
3. 次の 3 つのファイルを作る。**ファイル名は完全に一致させてください**（`Code.gs` が `post` / `admin` という名前で HTML を読み込みます）
   - `Code.gs` … スクリプトファイル
   - `post.html` … HTML ファイル（Apps Script 上の名前は `post`。リポジトリの `index.html` **ではありません**）
   - `admin.html` … HTML ファイル（Apps Script 上の名前は `admin`）
4. **プロジェクトの設定 → 「appsscript.json」マニフェスト ファイルをエディタで表示する** にチェックを入れ、`appsscript.json` の中身をリポジトリのものに合わせる
5. あとは A の 3 以降と同じ

デプロイ前に「3. 先生用管理画面を開く」を実行すると、URL が取れない旨の警告が出ます。先にデプロイしてください。

### 更新は「デプロイを管理 → 既存デプロイを編集」

「新しいデプロイ」を作ると `/exec` の URL が変わり、**学級に配ったリンクが全部切れます。**

### 編集室に入れる人（要設定）

編集室（`?p=admin`）と、記事一覧・タグ変更・一時保存・テンプレートなどの管理系サーバー関数は、**登録した先生のアカウントでしか使えません**。判定は `Session.getActiveUser().getEmail()` と `TEACHER_EMAILS` の照合で行い、画面だけでなくサーバー関数側でも同じ検査を通します（`google.script.run` から直接呼ばれても弾くため）。

- `TEACHER_EMAILS` 未設定のときは、**スプレッドシートのメニュー操作**を最初に実行した人のメールが `OWNER_EMAIL` として記録され、それと照合します。コピー直後のファイルはまだ誰とも共有されていないので、これは持ち主の先生になります。
- メールが取得できない場合（ドメイン外・未ログインなど）は拒否します。許可リストが空のときも拒否します（設定するまでは**誰も**入れない＝安全側）。
- **児童に URL を配る前に、必ず「2. 先生のメールアドレスを設定」を済ませてください。**

### 実行するユーザーは「自分」（`USER_DEPLOYING`）

`appsscript.json` の `webapp` は `executeAs: USER_DEPLOYING` / `access: DOMAIN` です。
サーバー側の処理は、誰が開いても**デプロイした先生の権限**で走ります。

- 児童は先生のスプレッドシートにもドライブにも**アクセス権が要りません**。
  児童がシートを直接開くことも、記録をいじることもできません。
- 同一 Workspace ドメイン内であれば、この形でも `Session.getActiveUser().getEmail()` で
  **画面を見ている本人**のメールが取れます（`access: DOMAIN` に限っているのはそのためでもあります）。
  取れなければ空文字になり、教員判定は `false` に倒れます（fail-closed）。
- ⚠️ **身元の判定に `Session.getEffectiveUser()` を使わないこと。** この形では
  effective user は児童が開いても「デプロイした先生」になるため、使った瞬間に
  学級全員が先生として通ります。`Code.gs` の `isTeacher_()` は `getActiveUser()` だけを見ます。

> 2026-08-23 に `USER_ACCESSING` から変更しました。以前の README には
> 「『自分』で実行すると利用者のメールが取れず、誰も編集室に入れません」と書いていましたが、
> これは `access` がドメイン外に開いている場合の話で、`access: DOMAIN` では当てはまりません。
> **この環境では GAS を実行できないため、本番での挙動は未確認です。**
> 最初のデプロイのあと、先生のアカウントで `?p=admin` が開けることを確かめてください。

### シートの点検と修整

コピーしたスプレッドシートは先生のものなので、列を足す・並べ替える・見出しを打ち直す、が起こります。
**何も言わずに壊れないよう、3 段に分けてあります。**

| 段 | 実装 | いつ動くか | 何をするか |
|---|---|---|---|
| 1 | `ensureSchema_()` | シートを触るたび（自動） | **足りないシートと、空のシートの見出し**だけを作る |
| 2 | `checkSchema_()` | メニュー「4. シートを点検する」 | どこがどう違うかを並べる。**何も書き換えない** |
| 3 | `repairSchema_()` | メニュー「5. シートを直す」 | 確認を取ってから、安全に直せるものだけを直す |

**修整でやるのは「足す」と「書き方をそろえる」だけです。消す・動かすは一切しません。**

| 見つかったもの | どうするか |
|---|---|
| シートが無い | 作る（見出し付き） |
| 空のシートに見出しが無い | 見出しを書く |
| 見出しの書き方が違う（`tag` / ` Tag `） | その 1 セルだけ正しい綴りにそろえる |
| 列が足りない | **右端に足す**（既存のデータは 1 セルも動かない） |
| 列が並べ替えられている | 直さない。読み書きは見出し名で行うのでそのまま動く |
| アプリが知らない列がある | 直さない。消さない。記事が届いてもそこは空のまま |
| 同じ見出しが 2 つある | 直さない（どちらを読むか決められない） |
| **1 行目がデータになっている** | **直さない。** 人に伝えて止まる |

最後の 1 つが要点です。見出しの行ごと消えているときに見出しだけ書き戻すと、
**間違った列に正しいラベルが付いて、事故が見えなくなります。**
そこは「1 行目に行を挿して見出しを戻してください」と伝えるだけにしてあります。

点検・修整のメニューは、`SpreadsheetApp.getUi()` を取ってから `isTeacher_()` を通す
2 段構えです（`getUi()` が例外になることを防御と数えないため）。

### 写真の公開範囲

投稿された写真は、まず **ドメイン内でリンクを知っている人だけが閲覧可**（`DriveApp.Access.DOMAIN_WITH_LINK`）に設定してドライブへ保存します。Google Workspace 以外のアカウントではこの設定ができないため、その場合は **非公開**（`PRIVATE`）へフォールバックし、登録済みの先生にだけ閲覧権を渡します（どちらになったかはログに残ります）。

表示用の URL は `https://drive.google.com/thumbnail?id=...` です。公開CDNの `lh3.googleusercontent.com/d/...` は「リンクを知っている全員」向けで、ドメイン限定・非公開のファイルでは表示できないため使いません。

## 実装上の注意（できないこと・気をつけること）

ドキュメントと実装がずれないよう、**現時点で実装されていないこと**を明記します。

- **承認フローはありません。** `Status` 列には `Pending` が書き込まれますが、この値をどこかで読んだり書き換えたりする処理は存在しません。編集室には投稿された記事がすべて出ます。「掲載する／しない」はチェックボックスの選択だけで決まります。
- **紙面は 1 ページ分だけです。** A4 の枠は `overflow: hidden` で、はみ出した記事は画面にも印刷にも出ません。段数・文字サイズ・写真の大きさで収めてください。
- **紙面上で直した文章は、スプレッドシートに戻りません。** 見出し・記者名・本文の書き換えはブラウザ内に持つだけです。「一時保存」しておかないと、再読み込みで消えます（記事一覧のタグ欄だけは例外で、直した瞬間にスプレッドシートへ書き戻されます）。
- **記事を削除する機能はありません。** 消せるのは、その場で足した自由記述欄だけです。投稿記事を消すにはスプレッドシートの行を直接消します。
- **「一時保存」は同じ名前でも上書きせず追記します。** 呼び出すと最新のものが復元されますが、一覧には同名の項目が並びます。（「テンプレート」は同名を上書きします。）
- **キーワード検索は本文を対象にしません。** タイトルと記者名だけを見ます。
- **絞り込み中も自由記述欄は常に表示されます。** タグ・日付の条件は投稿記事にだけ効きます。
- **タグ設定を変えても、投稿済みの記事のタグ文字列は変わりません。** 記事には選択時のタグ名が文字列として残ります。
- **QR コードにできるのは `http` で始まる URL だけです。**
- **オフラインでは動きません。** PWA 化していないため、`script.google.com` に接続できないと開けません（→ [AUDIT.md](AUDIT.md)）。ただし**学校のフィルタリングで CDN が塞がれても動きます**（下記）。
- **`SystemData` シートだけは、列を位置で読み書きします**（`Type` / `Name` / `Data` / `Date` の 4 列固定）。非表示シートでアプリが自分で作るものなので今はこの形ですが、`Articles` と違って並べ替えには耐えません。
- `post.html` の `.full-viewport`（`100dvh`）は CSS に定義されているだけで、現在どの要素にも付いていません。

### 同時アクセス

同じ時刻に複数の児童が送信してもデータが壊れないよう、書き込みには排他ロックをかけています（記事の保存は最大 10 秒待ち、タグの更新は最大 5 秒待ち）。待っても取れなかった場合は児童の画面にエラーが出て、自動で再送を試みます。

**ロックで囲むのは `appendRow` / `setValue` の 1 回分だけです。** 写真の保存（base64 の復号とドライブへの書き込み。1 件あたり数秒）とシートの点検は、ロックの外で先に済ませます。ここを一緒に囲むと 40 人ぶんが直列になり、合計が児童側の再送 3 回（2+4+6 秒）を追い越して、数人だけが黙って送信に失敗します。

`articleColumns_()` は、足りない列を足すときだけ自分で短いロックを取ります。**呼ぶ側はロックを持っていない状態で呼んでください**（入れ子で取ると本番では待って落ちます。`tests/schema.test.mjs` がこれを見張っています）。

## 使っている外部リソース

学校のネットワークは `unpkg.com` や `fonts.googleapis.com` を塞いでいることがあります。
**塞がれても動くもの（見た目だけ）に限って、外部から読んでいます。**

| 用途 | 読み込み先 | 塞がれると |
|---|---|---|
| CSS フレームワーク（記者ページ） | Pico.css 1.5.10（unpkg） | 字と余白が変わるだけ。入力も送信もできる（実測） |
| フォント | Google Fonts | 端末側のフォントに落ちるだけ |
| QR コード生成（編集室） | **同梱**（qr-creator 1.0.0 / MIT） | — |

QR は以前 cdnjs から読んでいましたが、塞がれると `<canvas>` だけが残り、
**読み取れない白い四角が紙面に刷られていました**（実測：塗られた画素 2500 → 0）。
アプリ全体は動くので気づけません。いまは `admin.html` に同梱してあり、
**CDN から取る実行コードは 0 バイト**です。

同梱ライブラリを更新する手順は `admin.html` の該当コメントに書いてあります。

## 開発

```bash
npm run check                            # 品質ゲート
npm test                                 # 検査そのものと、Code.gs のシート点検・修整のテスト
npm run ci                               # 上の2つを順に

node scripts/check-project.mjs --list    # 検査項目の一覧
```

`check` / `ci` という名前は決め打ちではありません。**正本の `deploy.yml` が
`quality` → `ci` → `check` の順に探し、どれも無ければ「飛ばします」と表示して
緑のまま本番へ push します**（v5 §5-4）。名前を変えるとゲートが無言で外れます。

CI が `pull_request` と `push` の両方でこの2つを回します。
**検査を直したら、わざと壊した入力で確かめるテストも一緒に直してください。**
「0件でした」だけでは、検査が動いているのか何も見ていないのか区別できません。
