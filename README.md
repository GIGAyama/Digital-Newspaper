# 📰 デジタル・クラス新聞社

児童が記事を書き、端末どうしで送りあい、**A4 の学級新聞として印刷（または PDF 保存）する**ためのアプリです。

**サーバーもデータベースもアカウントも要りません。** GitHub Pages 等に静的ファイルを置くだけで、その日の授業から使えます。記事は各端末のブラウザの中にだけ保存され、端末間のやりとりは **PeerJS（WebRTC）による直接通信**で行います。

- **公開URL:** <https://digital-newspaper.giga-school.com/>（`main` への push で自動デプロイされます）
- **くわしい操作手順:** [📖 MANUAL.md](MANUAL.md)
- **点検の記録:** [🔍 AUDIT.md](AUDIT.md)

### 3行でわかる使い方

1. 「✍️ 記事を かく」でタイトル・本文・名前・タグ・写真を入れて保存する
2. 「🗞️ 新聞を つくる」に切りかえると、書いた記事がそのまま紙面に組まれる
3. 印刷ボタンで A4 に刷る。ほかの人の記事は「🔗 つながる」であつめる

**教師用と児童用の区別はありません。** 同じ 1 つの画面で、書くことも紙面を組むことも
できます。児童だけでも、はじめから終わりまで新聞を作れます。

## ✨ このアプリでできること

### ✍️ 記事を かく

- タイトル・本文・記者名・タグ・写真（1枚）を書いて、端末に保存する
- 漢字にふりがな（ruby）が付いた画面で操作する
- 文字数カウンター、名前の引き継ぎ、コピーして新しく書く
- 書いた記事の状態が「したがき／おくった／のせて もらった」で分かる
- 記事を `.json` に書き出す・読みこむ（通信が使えない教室での受けわたし用）

### 🗞️ 新聞を つくる

- 集まった記事に**チェックを入れたものだけ**を紙面に載せる
- キーワード（タイトル・記者名・本文）／タグ／更新日の範囲で絞りこむ
- ドラッグ＆ドロップで掲載順を並べ替える
- 紙面の上で、新聞名・発行日・見出し・記者名・本文を**直接書き換える**
- 用紙の向き（A4 縦／横）、縦書き／横書き、段組み（1〜4段）、文字サイズ（8〜24px）
- テーマ 7 種・フォント 5 種・見出しスタイル 6 種
- 記事ごとに写真の位置・大きさ・形を変える／見出しを隠す／写真を消す
- 記事に URL を紐づけて、紙面に **QR コード**を刷り込む（動画などへの導線）
- 「編集後記」のような、投稿によらない**自由記述欄**を足す
- 編集途中の状態に名前を付けて保存し、あとから呼び出す
- レイアウトとデザインだけを**テンプレート**として保存し、別の号に適用する
- タグ（絵文字・名前・ふりがな）を編集する。つながっている端末にも配られる
- ブラウザの印刷機能で A4 に印刷、または PDF として保存する

### 🔗 端末どうしで記事を送りあう（P2P）

- **10文字のあいことばだけで接続。** 紙面を組む端末で「へやを ひらく」を押すと
  `ABC23-KM7PQ` のようなあいことばが出ます。ほかの端末はそれを入れるだけ。
  アカウント登録・ログイン・メールアドレスは要りません。
  見まちがえやすい `0` `O` `1` `I` `L` は使いません。入力は**小文字でも、区切りの
  「-」が無くても**通ります。
- **どの端末でも、あつめる側にも送る側にもなれます。** 役わりは固定されていません。
- **届いた記事は、既定では紙面に載りません。** あつめている人がチェックを入れて
  えらびます。自分が書いた記事は、書いた端末では既定でチェックが入ります。
- **載せてもらったことが、書いた人に返ります。** あつめている人がチェックを入れると、
  送った側の記事が「のせて もらった」に変わります。
- **つながっていないあいだに書いた記事は、つなぎ直した瞬間にまとめて送られます。**
- **タグ設定はあつめる側から配られます。** 教室でタグをそろえるためです。

### 📲 PWA（アプリとしてインストールできる）

- 画面右上の「**追加**」ボタンから、PC・タブレット・スマホに入れられます。
  iPad / iPhone の Safari は「インストール」の合図を出さない仕様のため、
  「追加」を押すと「共有 → ホーム画面に追加」の手順が画面に出ます。
- 一度読み込んだあとは Service Worker のキャッシュで、**ネットワークが無くても
  起動して記事を書き、紙面を組み、印刷できます**（P2P だけはネットワークが要ります）。
- 新しい版を配ると「あたらしい バージョンが あります」の帯が出ます。
  **押されるまで入れ替わりません**（記事を書いている最中に中身が変わらないため）。

## 🚀 導入・デプロイ

`index.html` を中心とした**静的ファイルのみ**で構成されています。ビルド作業は不要です。

1. このリポジトリをダウンロード、またはフォークします。
2. **GitHub Pages** やお好きな Web ホスティングに、次のファイルをそのまま置きます。

   ```
   index.html
   offline.html
   manifest.webmanifest
   sw.js
   favicon.png
   icons/
   vendor/
   ```

3. 公開された URL にアクセスすればすぐ使えます。

> **HTTPS での公開を推奨します。** PWA のインストール・オフライン動作（Service Worker）と、
> P2P 通信（WebRTC）は HTTPS 環境が前提です。

`.github/workflows/deploy-pages.yml` が `main` への push で GitHub Pages に自動デプロイします。
品質ゲートが落ちたら公開しません。

### 外部から読む実行コードは 0 バイトです

学校のネットワークは `unpkg.com` や `cdnjs.cloudflare.com` を塞いでいることがあります。
**塞がれると機能が黙って壊れる**ので、実行コードは 1 バイトも外から取りません。
PeerJS も qr-creator も `vendor/` に同梱してあります。

外から読むのは Google Fonts だけです。塞がれても端末側のフォントに落ちるだけで、
入力も通信も印刷もできます。

QR は以前 cdnjs から読んでいましたが、塞がれると `<canvas>` だけが残り、
**読み取れない白い四角が紙面に刷られていました**（実測：塗られた画素 2500 → 0）。
アプリ全体は動くので気づけません。

## 🗄 データの置き場所

すべて**その端末のブラウザの中**です。作者のサーバーにも、GitHub にも、
どこにも送られません。

**記事の文字は `localStorage` に、写真は `IndexedDB` に置いています。**
分けている理由は下に書きます。キーは必ず `dnp_` で始めます。

| キー | 中身 |
|---|---|
| `dnp_articles_v1` | 記事の文字（自分が書いたもの＋届いたもの）。**写真は入りません** |
| `dnp_states_v1` | 記事ごとの紙面設定（載せる／写真の位置・大きさ・形／QR の URL） |
| `dnp_desk_v1` | 紙面の作業状態（新聞名・発行日・レイアウト・自由記述欄・並び順・書きかえ） |
| `dnp_saves_v1` | 「一時保存」した状態（名前つき） |
| `dnp_templates_v1` | デザインテンプレート（名前つき） |
| `dnp_tags_v1` | タグ設定 |
| `dnp_client_id_v1` | この端末の識別子（だれが書いた記事かの区別だけに使う） |
| `dnp_mode_v1` | 最後に開いていた画面 |

| IndexedDB | 中身 |
|---|---|
| `dnp_photos_v1` の `photos` | 記事の写真（`Blob`）。キーは記事の ID |

**接頭辞の付いていないキーは、読みも書きも消しもしません。**
`localStorage.clear()` は使いません（同じオリジンに同居する他のアプリを巻き添えにするため）。
Service Worker も localStorage に一切さわりません。

### なぜ写真だけ IndexedDB なのか

`localStorage` は 1 オリジンあたり **5MB 程度**しかありません。写真を base64 で
そこに入れると、**写真つきの記事 40 本ほどで一杯**になります。

`IndexedDB` は端末の空きに応じた大きさまで入り（実測で **925MB**）、しかも `Blob` を
そのまま持てるので base64 の 1.33 倍という水増しも起きません。写真をこちらへ移した
ことで、記事 3 本（うち 2 本が写真つき）で `localStorage` の使用量は **916 バイト**に
なりました。

**では、なぜ全部を IndexedDB にしないのか。** `IndexedDB` の書き込みは非同期で、
Chromebook がメモリ不足でタブを捨てるときの `pagehide` では、最後まで書き終わる
保証がありません。記事の文字は `localStorage` の同期書き込みで確実に残します。
**写真は撮り直せますが、書いた文章は撮り直せません。**

### 写真は端末の中で小さくしてから持ちます

選んだ写真は、**長辺 1200px・JPEG 品質 0.82** に縮めてから保存します
（教室でふつうに撮った写真で 150〜300KB）。縮小は端末の中だけで完結し、
どこにも送りません。1200px あれば、A4 の 1 段組みで全幅に伸ばしても 160dpi ほど、
3 段組みなら 500dpi を超えます。

「記事を かく」画面の下に、この端末に溜まっている量と、使える量が出ます
（`navigator.storage.estimate()` の値）。**8割を超えると赤く**なります。
溜まりすぎたら、記事ごとの「📷 写真をけす」で空けるか、`.json` に書き出してから
消してください。

起動時に `navigator.storage.persist()` を呼んで、端末の空きが減ったときに
まとめて消されにくくしています（断られても動作は変わりません）。

### IndexedDB が使えない端末では

プライベートモードなどで `IndexedDB` が塞がれている場合は、**前の版と同じ形**に
落ちます。写真を data URL のまま記事に持ち、`localStorage` へ書きます。
そのときは容量の目安表示も 4.5MB のものに切り替わり、写真つきの記事は
40 本ほどが上限になります。アプリが動かなくなることはありません。

## 🔐 セキュリティ設計（守っていることと、守っていないこと）

サーバーを持たない構成のため、**サーバー側で認証・認可を行う余地がありません。**
何をもって安全としているかを明記します。導入判断の材料にしてください。

### 守っていること

| 項目 | 設計 |
|---|---|
| 記事の置き場所 | 各端末の `localStorage` のみ。開発者や作者のサーバーには一切送信しません |
| 端末間のやりとり | WebRTC による端末どうしの直接通信（P2P）。**中継サーバーに記事の中身は残りません** |
| 受信データの扱い | P2P で受け取ったものも、ファイルから読んだものも、必ず `normalizeArticle()` で形を整えてから使います。写真は `data:image/...;base64,` の形と大きさ（2MB まで）を両方みて、外れたものは捨てます |
| 画面の組み立て | 届いた文字はすべて `textContent` で入れます。`innerHTML` に流しこむところはありません |
| QR にする URL | `http` / `https` で始まるものだけ。`javascript:` は紙面に刷れません |
| CSP | `default-src 'none'` を土台に、`script-src 'self'`（外部から実行コードを読まない）、`connect-src` を PeerJS の仲介サーバーだけに限っています |
| ブラウザ保存領域 | 自アプリ接頭辞（`dnp_`）以外のキーを読み書き・削除しません。`localStorage.clear()` は使いません。IndexedDB も自アプリのデータベース（`dnp_photos_v1`）しか開きません |
| Service Worker | 自アプリ接頭辞（`digital-newspaper-`）のキャッシュだけを削除します。同一オリジンの他アプリを巻き添えにしません。`localStorage` にも `IndexedDB` にも触れません（品質ゲートが見張っています） |

### 守っていないこと（運用でカバーが必要）

| 項目 | 実態 |
|---|---|
| **あいことばは「宛先」であって「認証」ではありません** | どの端末につなぐかを指し示すものです。あいことばを知っている人は誰でもそのへやに接続でき、記事を送りこめます。総当たりは 10文字（約82兆通り）で現実的でなくなりましたが、**板書を写真に撮られれば同じことです。使い終わったらへやを閉じてください**（閉じると次は別のあいことばになります） |
| **画面の出し分けは防御ではありません** | 「記事を かく」と「新聞を つくる」は誰でも行き来できます。役わりを分けたい場合は、端末の管理（MDM・キオスクモード等）と併用してください |
| **CSP の `'unsafe-inline'` は外せていません** | 1枚の HTML にスタイルとスクリプトを直接書く構成のためです。`'unsafe-eval'` は不要で入れていないため、外部スクリプトの読み込みと外部への送信は塞がっています |
| **`frame-ancestors` は設定できていません** | `<meta>` の CSP では効かない指定で、GitHub Pages では HTTP ヘッダーを足せません。埋め込み禁止は今の構成では実現できません |
| **削除は取り消せません** | 記事を消すと戻せません。ブラウザの履歴・サイトデータの消去でも消えます |

> **個人情報の観点でのおすすめ運用**
> 「記者の名前」欄は出席番号やニックネームでも動作します。学校の方針に応じて使い分けてください。
> 写真に児童の顔が写るかどうかも、掲示・配布の範囲に合わせて決めてください。

## ⚠️ できないこと・気をつけること

ドキュメントと実装がずれないよう、**現時点で実装されていないこと**を明記します。

- **紙面は 1 ページ分だけです。** A4 の枠は `overflow: hidden` で、はみ出した記事は
  画面にも印刷にも出ません。段数・文字サイズ・写真の大きさで収めてください。
- **承認フローはありません。** 「載せる／載せない」はチェックボックスだけで決まります。
- **写真が届くのは、文字より少しあとです。** 記事の文字は同期で保存・表示されますが、
  写真は `IndexedDB` から非同期で読みこむため、起動直後の一瞬だけ写真が空のことが
  あります。P2P で届いた写真も、記事が一覧に出てから置き場所へ移ります。
- **Chromebook がタブを捨てた瞬間に選んでいた写真は、残らないことがあります。**
  文字は `pagehide` で確実に書きますが、写真の書き込みは非同期なので間に合わない
  ことがあります。
- **紙面の上で直した文章は、記事そのものには戻りません。** 見出し・記者名・本文の書き
  かえは紙面の作業状態（`dnp_desk_v1`）に持ちます。記事を直したいときは
  「記事を かく」画面で開いて直してください。
- **書き出した記事を送り返す機能はありません。** `.json` は片道です（あつめる側が
  読みこむためのもの）。
- **記事を送ったあとに取り消せません。** あつめる側の端末に残ります。
- **別の端末・別のブラウザで開くと、過去のデータは出てきません。** 端末を変えるときは
  `.json` に書き出して読みこんでください。
- **iOS Safari は 7 日間使わないと保存データを消すことがあります**（ITP）。
  ホーム画面に追加しておくと受けにくくなります。
- **PeerJS の公開シグナリングサーバーを使います。** 学校のネットワークで WebRTC や
  `0.peerjs.com` が塞がれていると接続できません。そのときは `.json` での受けわたしを
  使ってください。
- **同時接続は 1 クラス（40人程度）を想定しています。** それ以上は試していません。

## 🛠 開発

```bash
npm run check      # 品質ゲート
npm test           # 品質ゲートそのものを、わざと壊して確かめるテスト
npm run build:sw   # sw.js の版を先読み対象の中身から決めなおす
npm run ci         # 上の3つを順に（build:sw は --check）
```

`check` / `ci` という名前は決め打ちではありません。**正本のワークフローが
`quality` → `ci` → `check` の順に探し、どれも無ければ「飛ばします」と表示して
緑のまま本番へ push します。** 名前を変えるとゲートが無言で外れます。

**検査を直したら、わざと壊した入力で確かめるテストも一緒に直してください。**
「0件でした」だけでは、検査が動いているのか何も見ていないのか区別できません。

**`index.html` を直したら `npm run build:sw` を実行してからコミットしてください。**
これを忘れると Service Worker の版が変わらず、直した画面が端末に届きません。
CI が `--check` で見張っています。
